## 1. CU-01 : Estimer le backlog d'un projet

| Rubrique | Contenu |
|---|---|
| **Portée et niveau** | application CAPI · utilisateur |
| **Acteur principal** | Utilisateur (créateur de la session / utilisateur classique qui fait ses choix à chaque tours) |
| **Intervenants et intérêts** | <Utilisateur> : <veulent estimer la compléxité d'une tâche via des score présent dans des cartes, la carte est choisi avec l'accord de l'ensemble des utilisateurs pour essayer de limiter la subjectivité dans les choix> <br> <Créateur de session> : <Est une utilisateur classique qui crée les sessions de planning poker et a le droit de modifier les paramètres de la session afin d'optimiser la reflexion de tous (mise en place d'un timer...)> |
| **Déclencheur** | Le Créateur de la session lance l'application et invite les autres utilisateurs à participer au planning poker |
| **Garanties** | Minimales : Tout le monde arrive à se connecter à l'application · De succès : Connexion facile par les utilisateurs via un code ou lien d'invitation |

Les différents votes et statistiques intéressantes sont stocker dans un historique (JSON) pour aider l'utilisateur dans ses choix de carte ou en cas d'arrêt du jeu (carte café)
### Scénario nominal (5 à 7 étapes)

1. Le créateur de la session configure la partie dans l'application (nombre de joueurs, nom de joueur, mise en place de timer...).
2. Le créateur de session peut s'il le souhaite reprendre là où une session précédente s'est arrêtée via le fichier d'historique JSON.
3. Le créateur de session peut s'il le souhaite donner un nom à la tâche soumis au vote (qui sera le cas échéant inscrit dans le JSON).
4. L'ensemble des utilisateurs <u>Votent sur une fonctionnalité (CU-02)</u> et finiront par trancher en fonction de la règle de validation.
5. L'application enregistre le score gagnant du dernier vote dans le JSON puis passe au vote suivant.
6. Si la carte café est mise par l'ensemble des utilisateurs alors la session s'arrête et l'application exporte l'historique JSON.

### Extensions (3 obligatoires)

- **<étape>a.** Le backlog chargé est invalide :
  - <étape>a1. L'application détecte une erreur de format/structure (JSON attendu) et affiche un message d'erreur
  - <étape>a2. L'application détecte une erreur de structure (du fichier JSON) et affiche un message d'erreur
  - L'application demande à l'utilisateur de charger un fichier valide
- **<étape>b.** Tous les joueurs jouent la carte café :
  - <étape>b1. Tout les utilisateurs sélectionnent la carte café et la session est mise en pause
  - Sauvegarde de l'historique des votes, paramètres, statistiques... Dans le fichier JSON.
  - Exportation du fichier JSON
- **<étape>c.** L'utilisateur reprend une partie sauvegardée :
  - <étape>c1. L'application demande s'il y a besoin de reprendre une partie déjà initié
  - L'application demande le fichier de sauvegarde (JSON)
  - Les utilisateurs reprennent leur session là où ils s'étaient arrétés

## 2. Les 6 user stories

| US | Texte (En tant que... je veux... afin de...) | Source | MoSCoW |
|---|---|---|---|
| US-01 | En tant qu'utilisateur je veux pouvoir créer des sessions de jeu, sélectionner une carte et pouvoir afficher/cacher les cartes de tous les utilisateurs afin d'exprimer mon avis | www.scrumpoker-online.org | Must Have |
| US-02 | En tant qu'utilisateur je veux pouvoir choisir la règle de validation stricte pour le vote final de la carte afin de m'assurer que toute l'équipe est d'accord (unanimité) sur l'estimation | Sujet CAPI | Must Have |
| US-03 | En tant qu'utilisateur je veux que la première règle de validation soit la strict stricte pour le vote final de la carte afin de permettre une discussion quand les joueurs ne sont pas d'accord au départ | Sujet CAPI | Should Have |
| US-04 | En tant qu'utilisateur je veux pouvoir choisir une règle de validation parmi la moyenne, la médiane, majorité absolue, majorité relative pour le vote final de la carte afin de pouvoir trancher si les utilisateurs ne s'entendent pas  | Sujet CAPI | Could Have |
| US-05 | En tant qu'utilisateur créateur de la session je veux pouvoir modifier les paramètres de la session afin d'optimiser la réflexion de tous | Sujet CAPI | Could Have |
| US-06 | En tant qu'utilisateur je veux avoir des aides à la décision des cartes (journal d'historique, statistiques, UX optimisé...) afin de pouvoir voter de manière objective | Notre groupe | Could Have |


Parmi ces 6 US, 3 portent les règles de validation : règle stricte, règle choisie, premier tour à l'unanimité.
